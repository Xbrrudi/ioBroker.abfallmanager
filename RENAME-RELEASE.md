# First publication of ioBroker.wastemanager 0.21.8

PR #2 was merged into `main`, the existing repository is now `Xbrrudi/ioBroker.wastemanager`, and the renamed Codex environment has been tested. The retired `release.yml` is manually disabled in GitHub Actions. Keep it disabled and leave `iobroker.abfallmanager@0.21.7` available.

`0.21.8` is the first prepared version of `iobroker.wastemanager`. Publication and tagging require separate approval. The adapter migration and rollback steps are in [MIGRATION.md](MIGRATION.md).

## Checks before publication

- Review and merge the release PR after `check-and-lint`, the adapter tests and `verify-release` complete. The required matrix covers Node.js 22, 24 and 26 on Ubuntu, Windows and macOS. Repochecker 5.24.3 reports E3027 when macOS is omitted for a package that permits installation on macOS. Runner availability can delay the matrix.
- Check that GitHub still shows `release.yml` as manually disabled and that there are no pending legacy release runs. Keep previous tags, including `v0.21.7`, with their original releases.
- Recheck `npm view iobroker.wastemanager --registry https://registry.npmjs.org/`. The registry returned HTTP 404 on 2026-11-24. An E404 from the public registry means no package is visible and does not reserve the name. Investigate a published package or any other registry error before proceeding.

## Maintainer procedure after approval

1. In the successful **Test and Release** run for the approved commit on `main`, download `verified-release-<attempt>` and extract `iobroker.wastemanager-0.21.8.tgz`. Compare its SHA-256 with the digest printed by **Pack and verify release**. Keep that exact TGZ. The tagged workflow builds and verifies a package from the same commit and checks its integrity against npm.
2. Sign in interactively with the maintainer's npm account using `npm login --registry https://registry.npmjs.org/`, then confirm the account with `npm whoami --registry https://registry.npmjs.org/`. Publish the verified archive using `npm publish /absolute/path/iobroker.wastemanager-0.21.8.tgz --access public --registry https://registry.npmjs.org/ --ignore-scripts` and complete npm's authentication challenge.
3. Compare `npm view iobroker.wastemanager@0.21.8 dist.integrity --registry https://registry.npmjs.org/` with `sha512-` followed by the output of `openssl dgst -sha512 -binary iobroker.wastemanager-0.21.8.tgz | openssl base64 -A`. Verify installation in a separate test environment. Add the ioBroker maintainer with `npm owner add bluefox iobroker.wastemanager` and verify with `npm owner ls iobroker.wastemanager`.
4. Configure [npm Trusted Publishing](https://docs.npmjs.com/trusted-publishers/) in the new package settings. Select **GitHub Actions** and enter owner `Xbrrudi`, repository `ioBroker.wastemanager`, workflow `test-and-release.yml`, and leave **Environment** empty. Enable the direct publishing permission if npm offers a choice. Keep personal tokens out of GitHub Actions. Once the new path is confirmed, retire the old package's publisher entry.
5. After separate tag approval, tag the same approved `main` commit as `v0.21.8`. The tagged workflow requires successful checks, the full adapter matrix and archive verification. When npm reports the same integrity, the workflow skips the publish action and attaches the verified archive to the GitHub release. An integrity mismatch stops deployment. Investigate the difference before retrying. Future unpublished versions use the official ioBroker deployment action with Trusted Publishing.
6. After testing the new installation and migration, prepare [ioBroker Latest](https://github.com/ioBroker/ioBroker.repositories/blob/master/sources-dist.json) admission using key `wastemanager` and metadata and icon URLs under the renamed repository. [Stable](https://github.com/ioBroker/ioBroker.repositories/blob/master/sources-dist-stable.json) admission follows separately.
7. After the new package is available and the migration instructions have been validated, deprecate the old package with `npm deprecate 'iobroker.abfallmanager@*' 'Renamed to iobroker.wastemanager. Back up and follow https://github.com/Xbrrudi/ioBroker.wastemanager/blob/main/MIGRATION.md before migrating.'`. Deprecation keeps 0.21.7 installable. Retain existing instances for rollback.
